# CR-001: Migración de Socket Unix a TCP

## Fecha
2026-11-16

## Solicitado por
Requisito de Hito Final: "Servicio JobRunner accesible mediante red".

## Descripción del cambio
Migrar el transporte de comunicación cliente-servidor de socket Unix
(AF_UNIX) a TCP (AF_INET). Esto permite la operación remota en LAN/VPN.

## Motivación
El socket Unix solo permite comunicación local. El Hito Final exige
que el servicio sea accesible por red, con cliente remoto, whitelist
de IPs y manejo de desconexiones.

## Análisis de impacto

### Archivos afectados
- src/ipc.cpp: añadidas listen_tcp y connect_tcp.
- src/ipc.h: declaraciones TCP.
- src/config.h/cpp: nuevos campos bind_ip, port, allowed_ips.
- src/daemon.cpp: escucha en TCP, verifica whitelist.
- src/client.cpp: conecta por JOBRUNNER_HOST:JOBRUNNER_PORT.
- config.json: nuevos campos de red.
- verif/scripts: tests adaptados a TCP + 3 nuevos.

### Requisitos afectados
- RF-18: Protocolo documentado (ADR-0004).
- RF-19: Misma semántica local/remota.
- RF-20: Whitelist de IPs.
- RF-21: Mensajes fragmentados.
- RF-22: Tolerar desconexiones.
- RF-23: Rechazo fuera de límites.

### Riesgos
1. Seguridad: TCP expone el servicio. Mitigado con whitelist.
2. TIME_WAIT: tras kill -9 el puerto queda ocupado 60s. Tests usan puertos aleatorios.
3. Compatibilidad: scripts con JOBRUNNER_SOCKET deben migrar a HOST+PORT.

### Plan de pruebas
- TC-010: Flujo remoto completo.
- TC-011: Whitelist de IPs.
- TC-012: Mensajes fragmentados y carga grande.
- TC-001 a TC-021: Adaptados a TCP.

- Sin regresiones funcionales.
